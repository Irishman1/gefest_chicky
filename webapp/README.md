# Нарезка планировок — веб-приложение

Вход по приглашению → проекты (объекты) → этажи → загрузка PDF → фоновая нарезка
→ просмотр плана с подсветкой квартиры при наведении → скачать одну или все.

## Локальный запуск

```bash
pip install -r webapp/requirements.txt
```

Нужен ещё Tesseract OCR (для сканов без текстового слоя):
Windows — https://github.com/UB-Mannheim/tesseract/wiki, Linux — `apt install tesseract-ocr`.

```bash
set ADMIN_EMAIL=you@example.com
set ADMIN_PASSWORD=пароль-администратора
python webapp/run_local.py
```

Откройте http://127.0.0.1:8000 — под этой почтой и паролем вы администратор.
Данные (база + файлы) лежат в `data/` рядом с `webapp/`.

## Деплой на Railway

Собирается один Docker-контейнер (веб + фоновая нарезка в одном процессе).

1. Залить репозиторий (**корень которого — папка `Planing_gefest`**, не `webapp/`)
   на GitHub.
2. В Railway: New Project → Deploy from GitHub repo.
3. Railway сам найдёт [railway.toml](../railway.toml) и соберёт
   [webapp/Dockerfile](Dockerfile) — контекст сборки должен быть корень репозитория,
   это стандартное поведение Railway при указании `dockerfilePath`.
4. **Settings → Volumes**: добавить том, путь монтирования `/data`.
   Здесь живут база данных и все нарезанные файлы — без тома они пропадут
   при каждом деплое.
5. **Variables**: задать
   - `ADMIN_EMAIL` — почта администратора
   - `ADMIN_PASSWORD` — его пароль (администратор создаётся один раз при
     первом запуске, если пользователей в базе ещё нет)
   - `COOKIE_SECURE=1` — обязательно, раз сайт по HTTPS (Railway это даёт из коробки)
6. **Settings → Networking**: сгенерировать публичный домен.
7. После деплоя откройте сайт, войдите под `ADMIN_EMAIL`/`ADMIN_PASSWORD`,
   в «Админке» создайте код приглашения для остальных пользователей.

Проверено на вашем плане: нарезка этажа (19 квартир, 300 dpi) занимает
~60–70 секунд и ~650 МБ памяти на пике — тарифа Railway Hobby хватает
с запасом (лимит 8 ГБ RAM).

## Бэкап

В «Админке» → «Скачать бэкап» — один zip с базой и всеми файлами.
Восстановление — там же, «Восстановить из бэкапа» (перезатирает текущие данные,
после — перезапустите сервис).

Из командной строки на сервере (если есть доступ к оболочке контейнера):

```bash
python backup.py --out /data/backups/manual.zip
```

## Структура

```
webapp/
  app/
    main.py         — маршруты FastAPI
    db.py           — SQLite, схема
    security.py     — пароли, сессии, приглашения
    cutter.py       — обёртка над ../cut_apartments.py под сайт
    jobs.py         — фоновая очередь нарезки
    storage.py      — пути к файлам на диске
    backup_util.py  — бэкап/восстановление
    templates/, static/
  Dockerfile
  requirements.txt
  backup.py
```

Сама логика нарезки (векторный/растровый режим, OCR, сглаживание контура)
не дублируется — сайт использует [cut_apartments.py](../cut_apartments.py)
из корня репозитория напрямую.
